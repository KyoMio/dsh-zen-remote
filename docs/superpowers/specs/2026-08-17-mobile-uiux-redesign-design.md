# 移动端 UI/UX 重排（app 化）设计定稿

日期：2026-08-17 · 状态：方向已与用户对齐，原型待实机反馈 · 分支：`rework/mobile-uiux`

可交互原型：https://claude.ai/code/artifact/0f0169c4-c3f7-4dbb-8084-2b670ca95d60
（iPhone 上直接打开体验；桌面打开显示为手机框）

## 背景与目标

用户（iPhone + PWA standalone，经 dsh-mobile-pwa 网关公网访问）反馈手机端排版太挤，
要求按移动 app 的交互思路重排。本设计把 dsh-web-mobile 从「桌面布局的窄屏压缩」
改为「两级页面栈的 app 信息架构」。

验收基准：用户 iPhone PWA 实机。pad 走 PC 排版（≥1024px 保持 no-op 不动）。

## 信息架构（定稿）

两级页面栈，横向推入转场：

```
会话列表页（主屏，启动永远落这里）
 ├─ 顶部：workspace 名即切换器（点开弹单，含「全部」），右上设置页
 │   （原生设置项——官方设置弹窗入口、外观、语言等——收进这里）
 ├─ 工具 chips 一条横滑：插件入口扩展点，各插件注册入口动态渲染
 │   （任务看板 / SSH / 用量 / 插件市场 / Skill 管理…）；行尾「···」
 │   打开显隐自定义单（每个入口一个开关，用户选择持久化到本地）
 ├─ 会话列表：仅当前 workspace；运行中会话带状态点
 │   （2026-08-17 实机第三轮：行改圆角卡片风格——次级灰底 + 独立
 │   卡片 + 左侧 40px 图标块 + 标题/状态两行 + 右侧时间，参考
 │   Claude Code 移动端列表；FAB 改「＋ 新建会话」文字胶囊）
 └─ 右下 FAB：点按=当前 workspace 直接新建（2026-08-17 实机反馈：
     长按选 workspace 已取消——iOS 上长按触发系统文本选中，体验差；
     要换 workspace 先用顶部切换器）
     ↓ 点会话行
会话页
 ├─ 头部仅五件：返回 · 会话名+运行状态点 · 信息卡入口 · better-sidebar 入口
 │   （Chat/Trajectory 当前视图名 + 双点指示显示在会话名下方）
 ├─ 内容区：Chat / Trajectory 双视图，横滑切换（无常驻分段控件）
 └─ composer（毛玻璃，无上分割线——顶部约 26px 用 mask 渐变淡入，
     消息滚动到底部呈渐隐过渡；会话页头部保留细分割线）：
     分支/Todo mini chips（输入卡外、上方）
     + 输入卡[附件 chips 行（有附件时）· 输入框（min 两行，约 62px）]
     + [附件(最左) · 权限胶囊 · 模型胶囊 · …弹性空隙… · 上下文圈 · 发送]
```

## 关键决策（grilling 定稿，勿回退重议）

| 决策点 | 定稿 |
|---|---|
| 导航范式 | 抽屉思路保留但升格：会话列表即主屏，不做底部 Tab 栏 |
| 启动落点 | 永远落会话列表（推送深链除外，直达会话） |
| Chat/Trajectory | 收进信息卡的分段控件 + 内容区横滑为快捷路径；头部只留视图名+双点指示 |
| composer 常驻位 | 2026-08-17 用户看原型后修订：附件按钮最左；权限、模型为「图标+文字在右」胶囊，点开底部选择单切换（不做点击循环切）；上下文圈最右紧邻发送键；分支与 Todo 收为输入框上方 mini chips（对齐上游 v1.0.0 composer dock 做法）；原「展开面板」取消 |
| 模型选择单 | 模型与推理等级是两个独立维度（DSH 原生菜单即如此），选择单内分两组单选、各自带勾，选完不自动关（两维度常一起调）；胶囊文字显示「模型缩写 · 等级」（如 V4-Flash · Max） |
| 插件入口 chips | 列表页顶部 chips 是插件注册的扩展点（实现时动态读取，不硬编码具体插件）；行尾「···」开显隐自定义单，用户选择本地持久化；原生设置项一律进右上角设置页，不占 chips 位 |
| 统计栏 | 从底部撤销，全部进会话信息卡（会话页右上角 ⓘ） |
| 信息卡内容 | 统计（轮/步/TTFT/LLM 耗时/工具耗时/缓存）、模式徽标、subagent、分支、Chat/Traj 切换、导出日志/重命名/Fork/归档 |
| 手势 | 2026-08-17 实机第四轮修订：①内容区横滑切 Chat/Trajectory **移除**（用户否决）；②**新增左缘右滑=返回**（会话页回列表；有浮层/工作台开着则先关它）——原「不做边缘手势」禁令解除，但 dsh-mobile-pwa 遗留的 edge-swipe-back（history.back，对 SPA 无用且热区抢占）须同时移除让位；③浮层下滑关闭保留；长按 FAB 已取消 |
| 密度 | 骨架按 iOS 规格（44pt 触控、列表行 60px、17px 级标题），正文 15px 保信息量，留字号调节口子 |
| 皮肤 | 沿用 DSH 官方 design tokens + 深浅双主题，毛玻璃仅用于会话页头部与 composer 两处 |
| better-sidebar | 保留其自带移动端适配（全宽抽屉），本插件只在会话页头部给入口位；<768px 隐藏它自带的右上角固定开关簇（与头部入口重复，2026-08-17 实机反馈） |
| 2026-08-17 实机第二轮 | ① composer 权限/模型胶囊只留 SVG 图标（文字被挤没意义）；② 会话页头部底边线取消，改消息区顶部 mask 渐隐（与底部渐隐对称）；③ 头部工作台按钮换「右侧栏」图标（panel-right），ⓘ 与它同一图标族/尺寸/描边；④ 首页左上角加 logo（运行时引用站点自身 favicon，不在仓库分发商标资源）；⑤ 视口固定：整页不滚动（html/body 不参与滚动、无橡皮筋位移），只有会话列表与消息流内部滚动——FAB/顶栏/会话头部/输入区永远钉在原位；⑥ PWA 冷启动首帧安全区就位：viewport-fit=cover 必须存在于首帧 HTML（由 dsh-mobile-pwa 网关注入端保证），不能等插件 JS 迟到补 |
| 回合过程折叠 | 2026-08-17 用户提出：Chat 视图里同一回合内的过程动作（推理/思考块、工具调用块）默认折叠为一条紧凑摘要行（如「过程 · N 步」），点击展开/收起；最终回复文本始终展开。仅手机断点生效 |
| dsh-mobile-pwa | 只管通道（认证/推送/PWA 壳）；其 pwa/app.css 中与本插件重叠的排版规则在并装验证后裁掉 |

## 新增功能范围：移动端附件上传（2026-08-17 用户提出）

现状问题:DSH 现有的文件选择在**宿主机侧**弹原生文件浏览器（跑 DSH 的那台
Mac 上弹窗），手机远程访问时完全不可用。

要求:
- composer 附件按钮在手机上触发**客户机本地**选择器（`<input type="file" multiple>`，
  iOS 自动弹出 相册 / 拍照 / 选取文件 三选）,文件与图片都要支持;
- 选中后经网关（已配对令牌之后的 HTTPS 通道）上传到宿主机，落到会话可引用的
  位置，composer 显示可删除的附件 chips;
- 上传接口必须挂在 dsh-mobile-pwa 网关认证之后，并设大小/数量上限。

2026-08-17 S7.1 定稿修订（用户）：**所有附件统一一条通路**——一律落盘
.dsh-uploads/ + 输入区上部预览 chip（图片=缩略图、文件=图标+名，×可删）
+ 草稿追加 @路径，随用户文字**手动一次发送**；S7 首版的「图片 base64
内联直发」通路取消（官方附件 chips API 不开放，chip 由本插件在
input.dock 渲染，与草稿 @token 同源解析）。

实现前待调研（实现阶段第一件事）:
- DSH 是否已有文件上传 API;用户装的 dsh-at-file（@文件引用）与
  dsh-vision-toolkit（图像）能否复用其通路;
- 若无现成 API,host 半边端点归属:倾向放本插件 node half（本插件从纯 client
  变为带 host 半边）,dsh-mobile-pwa 网关只负责透传与认证,不各自造轮子。

## 范围外（本期不做）

- 设置弹窗、文件树/预览适配：沿用上游 v1.0.0 现状；
- dsh-web-ui 全家桶兼容规则：用户未装，保留上游代码不动也不扩展；
- 底部 Tab 栏、语音输入、多会话并行监控等新能力。

## 实施备注

  沿用其 `src/client/styles/` 分主题 CSS + effects 模块结构；
- 「会话列表为主屏」意味着把官方 sidebar/directory 的内容重组为整屏视图，
  实现时优先用官方 slots/services 取数据，避免抓 DOM；
