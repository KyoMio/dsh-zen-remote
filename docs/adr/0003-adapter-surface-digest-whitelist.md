# 适配器白名单按接口面摘要放行，wire 不变的上游补丁版零发版过桥

状态：Proposed（2026-10-28）

## Context

better-sidebar 适配器（PB-12/PB-15，现七版）的 `versions` 是**精确版本白名单**：上游每发一个版本，即便接口面（路由、方法、WebSocket）逐字未变，`normalizeAdapter` 也拒绝登记，装了新版本的主服务端远程会话退回隐藏档，必须 zen-remote 发一次版才能恢复桥接。0.26.1（性能补丁）与 0.28.2（cold-cwd OOM 修复）都是这种"wire 不变"的补丁——上游发版越勤，这条维护尾巴越长。

我们真正要保证的是**转发面没有超出核对过的范围**（fail-closed，宁可少转发），版本号只是它的代理变量。把白名单从版本号换成接口面本身，代理变量消失，wire 不变的上游版本自动过桥。

## Decision

适配器声明新增 `surfaces` 表：`{ [surfaceDigest]: '备注' }`，与 `versions` 并存（`versions` 保留，兼容两端旧版摘要比对）。服务端登记适配器时对**本机已装插件的实际构建产物**抽取接口面并计算摘要：

1. **抽取器**：从 `test/adapter-better-sidebar.test.cjs` 第 1 层的核对逻辑提炼成 `src/adapters/extract-surface.ts`——对插件 `lib/index.js` 抽取 `/sidebar/*` 路由字符串集合与 `ns.method` 分发表键集合（沿用现有正则与命名空间过滤），集合排序后 sha256 取 16 位十六进制。抽取器与适配器一一配套（better-sidebar 的抽取器认 better-sidebar 的分发表形状），不是通用静态分析。
2. **放行判定**：已装版本在 `versions` 里 → 放行（现状不变）；不在，但抽取摘要命中 `surfaces` → 放行，日志记 `bridged by surface digest <d> (version <v> unlisted)`；两者都不中 → 不登记（现状的隐藏档）。
3. **握手摘要不变**：注册表里适配器的声明摘要仍按路由表规范化哈希计算（wire 面没变，路由表就没变，摘要自然一致）——两端一致性判定不受影响；`plugins` 握手字段里上报的 `version` 仍是真实已装版本。
4. **测试**：`adapter-better-sidebar.test.cjs` 增加一例——对每个 fixture 版本（`/tmp/bs-versions/*`）算摘要，断言七个版本的摘要**全等**（0.25/0.26/0.28 系接口面确实不同，此断言钉住"抽取器输出稳定、不随代码格式漂移"）；`surfaces` 表的每个 key 必须等于某个已列版本的摘要（防手滑抄错）。

watcher（已有的 release 监控）与抽取器共用这份代码：新版本 wire 不变 → 摘要命中 → 零动作；wire 变了 → 摘要不命中 → 隐藏档 + watcher 报告，人工写适配（与今天一致）。

## 稳定性论证（为什么注释/格式/内部重构不会误伤）

- 摘要输入是**抽取出的字符串集合**，不是文件字节。npm 构建产物无注释；0.28.1→0.28.2 实测：内部 cwd 解析逻辑整个更换、client.js CSS map 重排，抽取集合逐字相同。
- 失败方向 fail-closed：bundler 改变字符串拼接方式、方法名改动态生成等导致抽取漂移时，结果是摘要不命中 → 退隐藏档，绝不会多转发一个未核对的方法。最坏情况等于现状（人工 re-bless），不劣于今天。
- 反方向（误相同）由测试第 4 条 + watcher 的人工报告兜底。

## Consequences

- 上游 wire 不变的补丁版本（如 0.26.1、0.28.2 这类）**不再需要 zen-remote 发版**，双端版本一致性压力同步减小。
- `versions` 变成长期只记录"wire 真变过"的节点版本（0.25.0 / 0.26.0 / 0.28.x），表不再线性膨胀。
- 引入一个新前提：**抽取器必须跟上上游的分发表形状**。若上游把方法表改成完全动态（抽取器抽不出 ≥45 个名字），摘要必然不命中——fail-closed，但要在日志里把"抽取器抽不到东西"与"接口面真的变了"区分开，watcher 好报警。
- 仅服务端放行侧的改动，子客户端、中继协议、握手字段零变化；旧版 zen-remote 子客户端连的服务端升级后，`plugins` 摘要比对依旧成立。
