## rework/public-auth-push（2026-08-16，公网部署改造）

| 决策 | 理由 |
| --- | --- |
| 身份从「按 IP 审批」改为「配对码 + 设备令牌 Cookie」 | 公网 NAT/CGNAT 下 IP 既不稳定也不专属，IP 即身份在公网失效 |
| 默认只监听 127.0.0.1，TLS 交给用户反代 | PWA（SW/推送）强制要求 HTTPS；网关不自持证书，降复杂度 |
| 仅信任回环/白名单 socket 的 X-Forwarded-*；本机直连=回环且无转发头 | 防伪造转发头；反代同机时外部请求源 IP 全是 127.0.0.1，必须靠转发头区分 |
| 配对码内存态、一次性、10 分钟、5 错锁 15 分钟 | 重启即作废更安全；持久化配对码没有需求支撑 |
| 状态文件 v2，v1 直接归档不迁移 | 旧的按 IP 记录在令牌模型下无意义 |
| 放弃零依赖，引入 web-push | aes128gcm + VAPID 手写风险远大于一个成熟依赖；原「零依赖」实现发的是假推送 |
| 推送用 generateRequestDetails + 自派发 HTTP | sendNotification 硬编码 TLS，无法黑盒测试；自派发同一代码路径覆盖生产与测试 |
| 通知不带对话正文 | 正文会路过 FCM/APNs/Mozilla 服务器，泄漏面不可控 |
| dsh-push.mjs 零注入 + 事件名环境变量配置 | 0811 严格注入下猜服务名会直接阻塞加载；事件名留待实机核对 |
| 早期响应先排干请求体（drainThen） | 未读完请求体就响应会毒化 keep-alive 连接（反代复用上游连接时是真实风险） |
